# 数据库与 HA 服务注意事项

- 先判断服务由原厂包、Patroni、集群管理器或其他组件管理。不要对受 Patroni 管理的 PostgreSQL 另建独立自启 unit，也不要绕过集群管理器启动或停止数据库，除非产品方案明确要求。
- PostgreSQL/HGDB：确认实际程序版本、数据目录、用户及产品支持的前台或 `pg_ctl` 模式、启动与停止语义、超时时间。服务停止模式对事务和恢复有影响；禁止推测某个关闭信号可适用于所有产品。`pg_isready` 反映连接接收状态，不证明业务 SQL、角色权限及主备状态正确。
- Patroni/etcd：确认配置文件、集群身份、仲裁、节点角色及健康检查。重启单节点前检查副本、quorum、故障切换风险和维护流程；启动后检查集群状态，而不仅是本机进程。
- pgpool-II/hgproxy：先确认产品及版本的前台标志、配置/HBA/PCP 路径、日志方式及 stop/reload 命令；不要假设不同版本参数相同。验证代理进程、后端节点健康和实际连接路由。
- 本地磁盘挂载、网络与远端依赖仅按实际情况加入；数据库数据目录不应被 unit 的通用沙箱配置意外变为只读。
